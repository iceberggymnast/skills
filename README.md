# skills

Claude Code에서 쓰는 스킬 5종입니다. 앞의 셋은 팀 개발에서 반복되는 작업 — 팀원이 읽을 git 텍스트를 쓰는 일, 팀원이 올린 PR을 리뷰하는 일, AI가 짠 코드를 내가 실제로 이해했는지 확인하는 일 — 을 매번 같은 절차로 돌립니다. 넷째는 그 바깥에서, 내 세션 로그를 통째로 읽어 무엇을 절차로 만들 값이 있는지 가려냅니다. 다섯째는 작업이 한 번도 던져주지 않는 영역을 따로 배웁니다.

다섯 스킬 모두 "AI가 대신 해준다"가 아니라 **사람 쪽에 남는 것을 관리하는 쪽**에 무게가 있습니다. `git-writing`은 팀원이 한 번에 읽을 수 있는 문장을 남기고, `pr-review-loop`는 사람이 에디터에서 직접 확인해야 할 항목을 따로 뽑아내며, `senior-mentor`는 AI가 짠 코드에 대한 이해 부채를 원장에 쌓아 재고 갚게 하고, `session-audit`은 로그에서 나온 진단을 실행에 옮기기 전에 검증해 걸러 내며, `cs-drill`은 작업이 만나지 않는 개념을 목록에서 꺼내 간격을 두고 다시 묻습니다.

> The skills in this repository are written in Korean.

## 스킬

| 스킬 | 하는 일 | 발동 시점 |
|---|---|---|
| [git-writing](git-writing/SKILL.md) | 팀원이 읽는 git 텍스트(PR 본문·이슈·커밋 메시지)를 한 번에 읽히게 쓴다 | "PR 써줘"·"이슈 올려줘" 또는 `gh pr create` 직전 |
| [pr-review-loop](pr-review-loop/SKILL.md) | 팀원이 올린 PR을 충돌 확인부터 머지 후 컴파일 검증까지 한 절차로 리뷰한다 | "PR 올라온 거 리뷰해줘" |
| [senior-mentor](senior-mentor/SKILL.md) | 고쳐주는 봇이 아니라 물어보는 사수. 이해 부채를 예측–대조로 재고, 모르면 가르친다 | 커밋·PR 직후(훅) 또는 `/mentor` |
| [session-audit](session-audit/SKILL.md) | 세션 로그를 전수 파싱해 자동화 후보를 뽑고, 실행 전에 검증·선별한다 | "세션 전수 분석해줘"·"내 작업 방식 분석해줘" |
| [cs-drill](cs-drill/SKILL.md) | 작업이 만나지 않는 CS 개념을 목록에서 꺼내 배우고, 간격을 두고 다시 묻는다 | "CS 공부하자"·"복습할 거 있어?" 또는 세션 시작(훅) |

### git-writing

PR·이슈의 섹션 골격은 대체로 이미 잘 돌아갑니다. 이 스킬이 고치는 것은 그 안의 문장입니다 — 결정·근거·반사실을 한 문장에 욱여넣은 고밀도 문장, 설명 없이 등장하는 내부 참조 코드와 전문용어, 한 문서 안에서 섞이는 어미. 새 템플릿을 강제하지 않고 문장 규칙만 얹습니다.

### pr-review-loop

충돌 확인 → 팀 머지 기준·설계 문서 대조 → 코드 리뷰 → (선별적) 이해도 대조 → 사람이 직접 확인할 항목 분리 → 코멘트 → 머지 → 컴파일 검증.

핵심은 **사람이 확인할 항목을 분리해 내는 단계**입니다. 게임플레이·연출처럼 자동 검증이 안 되는 변경은 사람이 에디터에서 봐야 하는데, 그 항목을 사용자가 요구하기 전에 O/X 체크리스트로 먼저 냅니다. 상태·저장·데이터 구조를 건드리는 PR이면 리뷰 결과를 말하기 전에 이해도 대조부터 걸립니다.

### senior-mentor

네 가지 모드로 돕니다.

| 모드 | 언제 | 하는 일 |
|---|---|---|
| R | 사용자가 직접 짠 코드를 커밋하려 할 때 | 사수 리뷰 후 AI 작성분과 분리 커밋 |
| C | 커밋·PR 직후 훅이 요청할 때 | 예측–대조로 이해 여부를 측정 |
| L | 대조에서 모른다고 나올 때 | 중단하지 않고 그 자리에서 가르침 |
| Q | 대화 중 개념 질문에 답하며 새 개념을 가르쳤을 때 | 커밋이 없어도 원장에 적재 |

"용어를 안다"를 "개념을 안다"로 치지 않습니다. 아는지 묻는 대신 "여기서 X를 지우면 뭐가 어떻게 깨지느냐"를 묻고, 결과를 `일치` / `짚었으나 틀림` / `모름` 셋 중 하나로 원장에 남깁니다.

### session-audit

`~/.claude/projects`의 세션 로그를 전부 파싱해 사용자 프롬프트 원본만 복원한 뒤, 같은 데이터를 두 갈래로 봅니다 — 분류 틀(스킬/플러그인/에이전트/CLAUDE.md)을 가지고 보는 쪽과, 틀 없이 백지에서 보는 쪽. 겹치는 지점은 신뢰도가 높고, 갈라지는 지점이 대체로 더 중요합니다.

절차의 절반은 분석이 아니라 **거르는 일**입니다. 백지 분석이 내놓는 *"그 산출물을 한 달간 쓴 적이 없다"* 류의 지적은 결론이 아니라 가설이라, 파일 하나 열어보면 판정됩니다. 검증 결과를 적는 절이 비어 있으면 그 실행은 실패로 칩니다. 살아남은 제안도 세 관문(매주 반복되는가 · 잔여 수명이 긴가 · 작동 여부를 확인할 방법이 있는가)을 통과해야 목록에 남습니다.

분석 시작 전에 데이터 창부터 확인합니다. `cleanupPeriodDays`가 미설정이면 30일치만 남고 조용히 지워지므로, 이 확인을 건너뛰면 잔존 로그의 범위를 사용 기간으로 읽게 됩니다.

### cs-drill

`senior-mentor`가 재는 것은 **이미 있는 코드를 설명하는가**입니다. 그래서 원장에 쌓이는 개념은 그 사람의 작업이 실제로 부딪힌 것뿐입니다 — 그래픽스 작업을 하면 그래픽스 개념이 쌓이고, 자료구조나 네트워크는 몇 달을 돌려도 한 건도 안 나옵니다. 고장이 아니라 정상 작동의 결과입니다.

이 스킬은 반대 방향입니다. 재료가 작업이 아니라 **목록**에서 옵니다. 커리큘럼과 진도는 별도 원장(`cs-progress.md`)에 두고, 이해 부채 원장과 섞지 않습니다 — 한쪽은 이해 부채를, 한쪽은 미학습을 재기 때문에 합치면 분포가 두 지표의 혼합이 됩니다.

안 배운 것에 예측을 요구하지 않습니다. 첫 노출은 상황을 주고 설명한 뒤 이름을 붙이는 순서고, 며칠 뒤 다시 물을 때는 개념 정의가 아니라 **적재해 둔 판별점이 성립하는 새 상황**을 냅니다. 정의를 다시 말하게 하면 통과해도 아는 층이 그대로입니다.

세션 시작 훅은 기한이 지난 항목의 **개수만** 알립니다. 개념명을 알리면 노트를 먼저 읽고 답할 수 있어 재대조가 무효가 됩니다.

## 설치

### 플러그인으로

```
/plugin marketplace add iceberggymnast/skills
/plugin install dev-skills@iceberggymnast-skills
```

설치 화면에서 범위를 고르면 끝입니다. 요약에 `Run /reload-plugins to activate.`가 뜨면 그 명령을 한 번 실행합니다. 다섯 스킬이 함께 들어오고, 호출명에 플러그인 이름이 붙습니다 — `/dev-skills:senior-mentor`.

**단, `RATIONALE.md`는 스킬 폴더에 만들지 마세요.** 플러그인은 캐시 디렉터리로 복사되고 `/plugin update` 때 그 디렉터리가 갈립니다. 위치는 [BOOTSTRAP 2-7](senior-mentor/BOOTSTRAP.md)의 주의 문단을 따릅니다.

### 폴더 복사로

폴더째 `~/.claude/skills/` 아래에 복사합니다.

```
~/.claude/skills/
├── cs-drill/
├── git-writing/
├── pr-review-loop/
├── senior-mentor/
└── session-audit/
```

(`.claude-plugin/`은 플러그인 배포용 메타데이터라 이 방식에서는 복사하지 않습니다.)

레포를 `skills/` 폴더 자체로 clone하지 마세요. 그 디렉터리는 하위 폴더의 `SKILL.md`를 찾는 스캔 대상이라, README·LICENSE 같은 낱개 파일이 스킬 폴더와 같은 층에 섞입니다. 임시 위치에 clone한 뒤 스킬 폴더 다섯 개만 복사합니다.

**에이전트를 둘 이상 쓴다면 두 번째 쪽에는 복사하지 마세요.** `SKILL.md`가 두 벌이 되어 규칙을 고칠 때 한쪽만 고치게 됩니다. 스킬 폴더를 하나씩 링크해 실체를 한 벌로 둡니다 — 절차와 주의점은 [BOOTSTRAP 0-1](senior-mentor/BOOTSTRAP.md#0-1-claude-code-밖에서도-쓸-거면)에 있습니다.

## 처음 받았다면

**`session-audit`은 단독으로 돕니다** — 아래 절차가 필요 없고, 폴더만 복사하면 바로 씁니다. **`cs-drill`은 원장 하나만 있으면 됩니다** — `cs-progress-template.md`를 `~/.claude/cs-progress.md`로 복사하고 커리큘럼을 자기 것으로 고치면 시작할 수 있습니다(설명 순서는 `mentee-profile.md`가 있으면 그쪽을 따르고, 없어도 돕니다). 나머지 셋 중 **`senior-mentor`와 `pr-review-loop`는 세트입니다.** 이해 부채 원장(`comprehension-debt.md`)과 도입 절차를 공유하고, 한쪽이 적재한 기록을 다른 쪽이 소비하도록 설계되어 있습니다. 하나만 받으면 지표의 절반이 빕니다.

두 스킬은 사용자 프로필(`mentee-profile.md`)과 원장 두 개를 전제로 동작합니다. 이 파일들이 없으면 스킬은 발동은 하되 **조용히 값을 남기지 못합니다** — 실패가 눈에 보이지 않는 종류라 도입 시점에 한 번에 갖춰야 합니다.

[senior-mentor/BOOTSTRAP.md](senior-mentor/BOOTSTRAP.md)가 그 절차입니다. 원장 만들기, 프로필 인터뷰, 훅 세팅, 도입 확인 체크리스트까지 순서대로 있습니다. **다섯 스킬 모두 성공 기준을 `RATIONALE.md`에 두는데, 이 파일은 원작성자의 관측 기록이라 배포에 포함되지 않습니다.** BOOTSTRAP 2-7의 형식대로 각자 만들면 됩니다.

훅 두 개가 함께 들어 있습니다. 커밋·PR 직후 자동 발동에 쓰는 `senior-mentor/hooks/comprehension-gate.ps1`(세팅 절차는 BOOTSTRAP 3단계)과, 복습 기한을 알리는 `cs-drill/hooks/cs-due.ps1`(`SessionStart`에 등록)입니다. **둘 다 선택입니다** — 없으면 명시 호출로 씁니다.

## 호환성

| 항목 | 내용 |
|---|---|
| 에이전트 | Claude Code 기준입니다. 다른 에이전트에서도 쓰며, 그쪽에 스킬 스캔이 있느냐로 절차가 갈립니다(BOOTSTRAP 0-1). 스캔이 있으면(codex의 `~/.codex/skills` 등) 스킬 폴더를 복사하지 말고 링크해 한 벌로 둡니다. 어느 쪽이든 그쪽 전역 지침에 프로필을 가리키는 한 줄은 심어야 원장이 이어집니다 |
| 훅 | Claude Code의 `PostToolUse`·`SessionStart` 전용입니다. 다른 에이전트에서는 훅 없이 명시 호출로 씁니다 |
| OS | 훅이 PowerShell 스크립트라 Windows가 기본입니다. macOS·Linux는 PowerShell 7(`pwsh`)을 설치해 등록 명령을 바꾸거나, 훅 없이 씁니다 |
| 인코딩 | 한글이 든 `.ps1`은 UTF-8 BOM으로 저장해야 합니다. BOM이 없으면 Windows PowerShell 5.1이 cp949로 읽어 구문 오류로 죽습니다 |
| Python | `session-audit`의 추출 스크립트만 Python 3이 필요합니다. 표준 라이브러리만 씁니다. 읽는 로그 형식이 Claude Code의 `~/.claude/projects/*/*.jsonl` 전용이라 다른 에이전트 로그에는 파서가 따로 필요합니다 |
