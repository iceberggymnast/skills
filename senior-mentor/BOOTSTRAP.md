# BOOTSTRAP — `senior-mentor` · `pr-review-loop` 도입 절차

**두 스킬 공통 문서다.** `senior-mentor` 폴더에 두는 이유는 이쪽이 훅·프로필·원장 의존이 강해 부트스트랩 없이는 사실상 못 돌기 때문이다. `pr-review-loop`만 받아 가는 경우에도 이 파일이 필요하다 — 원장을 공유한다.

이 두 스킬은 **혼자 돌지 않는다.** 원장 두 개와 멘티 프로필, 훅 하나를 공유하고, 전역 `CLAUDE.md`의 규칙 몇 개를 전제한다. 그것들이 없으면 스킬은 발동은 하되 **조용히 값을 남기지 못한다** — 실패가 보이지 않는 종류라 도입 시점에 한 번에 갖춰야 한다.

새 사람이 이 세트를 받으면 아래를 순서대로 진행한다. 순서는 의존 관계 순이다.

---

## 0. 배치

```
~/.claude/
  skills/
    pr-review-loop/SKILL.md
    senior-mentor/SKILL.md
    senior-mentor/BOOTSTRAP.md  ← 이 파일
  comprehension-debt.md   ← 1단계에서 생성
  mentor-log.md           ← 1단계에서 생성
  mentee-profile.md       ← 2단계에서 생성
  hooks/
    comprehension-gate.ps1 ← 3단계 (선택, 배포판 senior-mentor/hooks/에 포함)
  CLAUDE.md               ← 4단계
```

`skills/` 바로 아래에는 **스킬 폴더만** 둔다. 그 디렉터리는 하위 폴더의 `SKILL.md`를 찾는 스캔 대상이라, 낱개 문서를 놓으면 다른 스킬과 같은 층에 섞인다. 스킬에 딸린 문서는 그 스킬 폴더 안에 둔다.

**기준 폴더를 먼저 정한다.** 홈 디렉터리에 `~/.claude`와 `~/.codex`가 있는지 확인하고, **`~/.claude`가 있으면 그쪽이 기준 폴더다** (둘 다 있어도 `.claude` 우선). `~/.codex`만 있으면 같은 구조를 그 아래에 만든다. 위 배치도의 경로는 전부 이 기준 폴더 아래다.

원장·프로필을 만들면 **그 절대경로를 `mentee-profile.md`에 적는다** (2단계). 기준 폴더를 직접 읽지 못하는 다른 에이전트(codex 등)가 같은 원장을 참조하는 통로다. **스킬 문서 안에는 절대 경로를 박지 않는다** — 사람마다 홈 디렉터리가 다르다. 절대경로는 프로필(개인 파일)에만 둔다.

### 0-1. Claude Code 밖에서도 쓸 거면

정할 것이 **두 가지**다. 문서를 그 에이전트가 볼 수 있는 곳에 두는 일(배치)과, 그 에이전트가 그 문서를 실제로 열게 만드는 일(발동)이다. 둘을 뭉치면 답이 하나뿐인 것처럼 보인다 — 실제로는 각자 다른 선택지가 있고, 에이전트에 따라 한쪽만 필요하기도 하다.

#### 발동 — 스킬 스캔이 있는지 먼저 본다

그 에이전트의 홈에 스킬 디렉터리가 있는지 확인한다. codex는 `~/.codex/skills`다. 있고 그 안의 `SKILL.md`가 `name`·`description` frontmatter 형식이면 **스캔이 있는 쪽**이다 — description만 먼저 읽어 두고 필요할 때 본문을 여는 방식이라, Claude Code와 같다. 확인 시점(2026-08) codex 0.145가 그렇다. 버전마다 다를 수 있으니 자기 버전에서 직접 확인한다.

스캔이 없는 에이전트라면 누군가 가리켜 줘야 한다. 그 에이전트의 **전역 지침 파일에 한 줄을 심는다.** codex는 `~/.codex/AGENTS.md`이고, 다른 도구도 각자 그에 해당하는 파일이 있다.

```markdown
멘토 스킬 세트를 쓸 때는 `<기준 폴더 절대경로>/mentee-profile.md`를 먼저 읽는다.
원장 위치와 스킬 폴더 경로가 그 파일 상단에 있다.
```

**한 줄이면 끝난다.** 프로필이 원장 두 개와 볼트 경로를 이미 들고 있으므로(2단계·2-8), 프로필만 찾으면 나머지는 따라온다. 전역 지침에 경로를 여러 개 늘어놓으면 프로필을 옮길 때 갱신할 곳이 늘어난다.

**스캔이 있는 에이전트에서도 이 한 줄은 남긴다.** 스캔 대상은 스킬 폴더뿐이고 프로필과 원장은 그 밖에 있다 — 스킬은 발동하는데 원장을 못 찾는 상태가 된다.

기준 폴더가 `~/.codex`인 경우에도 같다. `SKILL.md` 본문의 `~/.claude/...` 표기는 기준 폴더를 가리키는 관용 표기이므로, 실제 위치는 프로필이 정한다.

#### 배치 — 복사하지 말고 링크한다

**스킬 문서를 그 에이전트 쪽으로 복사하지 않는다.** 복사하면 `SKILL.md`가 두 벌이 되어 규칙을 고칠 때 한쪽만 고치게 되고, **형식이 다른 두 에이전트가 같은 원장에 쓰는 상태**가 된다. 원장을 하나로 두는 이유가 그대로 문서에도 적용된다. 원본과 사본의 날짜가 몇 주씩 벌어져도 겉으로는 양쪽 다 멀쩡히 도는 것처럼 보이므로, 눈치채는 데 오래 걸린다.

스캔이 있는 에이전트에서 그쪽 스킬 목록에도 올리고 싶다면 **복사 대신 링크한다.** 실체가 한 벌이라 위 문제가 생기지 않는다.

```
<그 에이전트 홈>/skills/senior-mentor  →  <기준 폴더>/skills/senior-mentor
```

두 가지를 지킨다.

- **스킬 하나씩 건다. `skills` 디렉터리를 통째로 걸지 않는다.** 그 디렉터리에는 에이전트가 스스로 관리하는 스킬도 들어 있어서(codex는 시스템 스킬과 런타임 스킬을 그 아래 둔다), 통째로 덮으면 그것들이 사라진다.
- **걸고 나서 그 에이전트가 실제로 목록에 잡는지 확인한다.** 스캐너가 링크를 따라가는지는 도구마다 다르다. Claude Code는 따라간다. 아래 원장 쓰기 확인과 같은 이유로, 확인 전까지는 됐다고 치지 않는다.

Windows에서는 디렉터리 정션(`mklink /J`)을 쓴다. 심볼릭 링크와 달리 관리자 권한이 필요 없다.

**링크가 해결하지 않는 것도 분명히 해 둔다.** 훅은 여전히 Claude Code 전용이고(3단계), 원장에 한 번에 한 에이전트만 붙이는 규칙도 그대로다. 링크가 대체하는 것은 복사이지 앵커가 아니다.

**어느 쪽으로 붙였든, 그 에이전트에서 쓰기 시작하기 전에 원장에 실제로 한 줄이 쓰이는지 확인한다.** 원장은 그 에이전트의 작업 폴더 밖에 있으므로, 샌드박스가 작업 폴더 쓰기만 허용하면 **문서는 읽히고 적재만 조용히 실패한다** — 스킬이 도는 것처럼 보이는데 아무것도 안 쌓이는 상태다. codex라면 `~/.codex/config.toml`의 `sandbox_mode`와 홈 디렉터리 신뢰 설정이 그것을 정한다. 2-8에서 MCP 볼트에 쓰기 테스트를 한 번 하는 것과 같은 이유다.

**두 에이전트를 동시에 띄우고 작업하면 원장이 덮인다.** 마크다운 추가 쓰기라 실제로 겹칠 확률은 낮지만, 한쪽에서 커밋하고 다른 쪽에서 리뷰하는 식으로 병행하는 사람에게는 실재하는 손실이다. 잠금 장치는 없으므로 한 번에 한 에이전트만 원장에 붙인다.

`RATIONALE.md`는 배포에 포함하지 않는다. 원작성자의 관측 기록이라 받는 쪽에는 의미가 없고, 필요하면 각자 자기 것을 만든다.

## 1. 원장 두 개 만들기

두 스킬이 **같은 파일에 쓴다.** 나누면 지표가 갈라져서 분포를 못 잰다.

### `~/.claude/comprehension-debt.md`

이해 부채 원장. 아래 네 섹션이 반드시 있어야 한다. 하나라도 빠지면 스킬이 적재할 곳을 못 찾는다.

| 섹션 | 담는 것 |
|---|---|
| `## 대조 집계` | 모든 대조 결과 한 줄씩. 컬럼은 `날짜 \| 출처 \| 영역 \| 개념 \| 결과`, 결과 값은 `일치` / `짚었으나 틀림` / `모름` 셋. 여기에 `pr-review-loop`이 쓰는 `읽지 못함`(개념이 아니라 분량 때문에 못 짚음)과 `사용자 선행`(리뷰가 놓친 것을 사용자가 먼저 짚음)이 더해지며, **이 둘은 학습 분포에서 뺀다** |
| `## 영역별 숙련도` | `레포 + 기술 스택` 단위. 컬럼은 `영역 \| 상태 \| 관찰 \| 갱신일 \| 비고`, 상태는 `미측정` / `C`(숙련) / `L`(미숙) |
| `## 부채 항목` | `모름`·`짚었으나 틀림`만 정식 항목으로. 형식은 **사례 먼저, 정의 나중** |
| `## 스킵 기록` | 사용자가 생략을 요청한 건. `senior-mentor`의 1차 지표다 |

**`일치`도 집계에 남긴다.** 분모가 없으면 분포를 못 재고, 항목 수만으로는 "노출이 줄어 안 쌓인 것"과 "실력이 늘어 안 쌓인 것"이 구분되지 않는다.

부채 항목 템플릿 (두 SKILL.md가 쓰는 형식과 같아야 한다):

```markdown
### YYYY-MM-DD [영역] 개념명  (커밋 a1b2c3d 또는 PR #47)
- 겪은 것: (어떤 질문에 답을 못 했는지 / 무엇을 되물었는지)
- 실제: (그 코드가 실제로 하는 일)
- 이름: (CS·엔진 용어)
- 판별점: (이미 알던 층 → 몰랐던 층)
- 갭 위치: (두 층이 서로 다른 스택에 걸쳐 있을 때만. 한 스택에서 완결되면 생략)
- 예측 상태: 모름 | 짚었으나 틀림
- 복습 체크: [ ] 1회차  [ ] 2회차
```

**`## 부채 항목` 아래에 "판별점"·"갭 위치" 두 절도 함께 만든다.** 두 SKILL.md가 "형식·예시는 그 파일의 '판별점' 절이 기준"이라고 참조하는 곳이라, 없으면 참조가 허공을 가리킨다. 아래를 그대로 옮긴다.

> **판별점 — 주제가 아니라 "틀린 그 지점"을 적는다.** 개념명은 주제일 뿐이라, 그것만 보고 복습 질문을 만들면 이미 알던 층을 묻게 된다. 그래서 판별점은 두 층을 화살표로 적는다.
> ```
> 판별점: 상태에 수명이 있다는 것(알던 층) → 접근 코드가 동일한 여러 그릇이 있고
>   어느 그릇이냐가 수명을 정한다는 것(몰랐던 층)
> ```
> 겨냥 질문은 판별점을 물어야 한다. 알던 층을 물어 맞힌 것은 집계에 남기되 그 항목의 복습 체크는 닫지 않는다.
>
> **갭 위치 — 어느 스택에서 닫히는가.** 판별점의 두 층이 서로 다른 스택에 걸쳐 있을 때만 `갭 위치` 한 줄을 덧붙인다. 아는 쪽이 A 스택이고 빈 곳이 B 스택이면 A 스택 코드로는 그 항목이 닫히지 않는다 — 아는 쪽을 묻게 되기 때문이다.
> ```
> 갭 위치: UE 메커니즘. Unity 코드로는 닫히지 않는다 — 아는 쪽을 묻게 된다
> ```

**복습 체크는 다시 읽어서 닫히지 않는다.** 조건은 "이후 대조에서 같은 개념을 예측으로 맞힘"이고, 근거는 `## 대조 집계`에 그 개념이 `일치`로 남는 것이다. 설명을 들어 납득한 것은 체크가 아니다.

### `~/.claude/mentor-log.md`

`senior-mentor` 모드 R(사용자가 직접 짠 코드) 리뷰 기록. 빈 파일로 시작해도 된다. 형식은 스킬의 5단계에 있다.

프로젝트별로 쪼개지 않는다 — 같은 습관은 프로젝트를 넘어 반복되므로 한 파일에 태그만 붙여 쌓는다.

## 2. 멘티 프로필 만들기

`~/.claude/mentee-profile.md`. **이 파일이 없으면 `senior-mentor`는 리뷰를 시작하지 않는다.** 프로필 없이 설명하면 아는 것을 다시 가르치거나 모르는 것을 건너뛴다.

프로필 상단에 **원장 두 개(`comprehension-debt.md`·`mentor-log.md`), 이 프로필 자신, 그리고 스킬 폴더의 절대경로**를 적는다 (0단계에서 정한 기준 폴더 기준). `~/.claude`를 직접 읽지 못하는 에이전트(codex 등)에서 이 스킬 세트를 쓸 때 그 절대경로로 같은 원장을 참조한다 — 에이전트마다 원장이 갈라지면 분포를 못 잰다. **스킬 폴더 경로도 함께 적는 이유는 0-1의 앵커가 프로필 하나만 가리키기 때문이다** — 그 에이전트는 `SKILL.md`를 스스로 못 찾으므로, 프로필이 문서 위치까지 이어주지 않으면 원장은 찾고 스킬 본문은 못 찾는 상태가 된다.

### 2-1. 인터뷰

아래를 본인에게 묻고 답을 그대로 적는다. 추측해서 채우지 않는다.

1. **전공·경력 배경과 주력 스택은?** — 비유의 재료가 여기서 나온다
2. **학술 용어와 실전 경험 중 어느 쪽이 강한가?** — **설명 순서가 여기서 갈린다.** 실전이 강하면 경험 → 용어 순, 이론이 강하면 반대
3. **가장 익숙한 영역은?** — 아래 2-2로 이어진다
4. **지금 낯선 영역은?** — 새 언어·엔진·도메인. 초기 `L` 판정의 출발점이 된다
5. **톤 선호** — 언어, 직설/완곡, 금지 표현
6. **커밋·PR·리뷰를 LLM 안에서 하나, 밖에서 하나?** — IDE에서 커밋하고 GitHub 웹에서 리뷰·머지하는 사람이면 **이 스킬 세트가 덮는 범위가 줄어든다.** 아래 2-6에서 다룬다

> 6번은 도입 전에 알아야 할 항목이다. 3주 뒤 빈 원장을 보고 "안 쓰네"로 오진하는 것보다 지금 한 줄 묻는 게 싸다.

### 2-2. 익숙하다는 영역에 도메인 질문 2~3개

**자기 보고만으로 숙련도를 정하지 않는다.** 이 스킬 자체가 "용어를 안다고 개념이 체화됐다고 가정하지 않는다"를 원칙으로 두고 있는데, 프로필을 자기 보고로만 채우면 도입 시점에 그 원칙을 어긴다. 초기 `C`/`L` 판정이 통째로 틀어진다.

3번에서 나온 영역에 대해 **예측형 질문 2~3개**를 던진다. 모드 C의 질문 규칙을 그대로 쓴다.

- ❌ "싱글톤 아세요?" — 아는지 묻는 질문은 측정이 안 된다
- ⭕ "이 상황에서 X를 지우면 뭐가 어떻게 깨집니까"
- ⭕ "이 접근이 실패하는 케이스와, 각각 어떤 조건에서 터지는지"

**질문은 그 영역의 A등급 지점을 고른다** — 라이프사이클 순서, 수명·소유권, 버전 의존 API. 그 영역에서 AI 코드가 조용히 틀리는 자리다.

결과는 프로필의 **강한 축 / 약한 축**으로 적는다. 익숙하다고 했는데 예측이 빗나가면 그 사실을 적는다 — 틀렸다는 기록이 아니라, **어디부터 설명해야 하는지의 좌표**다.

> 이 질문들은 `## 대조 집계`에 넣지 않는다. 도입 인터뷰는 코드 변경에 대한 대조가 아니라서 분모의 성격이 다르다.

### 2-3. 기존 세션 로그 대조 (허가 필요)

**발동 타이밍은 사람마다 다르다.** 어떤 사람은 "커밋해줘"라고 하고 어떤 사람은 "이거 올려줘"라고 한다. 스킬의 트리거 문구가 실제 말버릇과 안 맞으면 **스킬은 존재하되 한 번도 안 걸린다** — 이 세트의 1차 실패 모드가 정확히 그것이다.

**먼저 허가를 받는다.** 본인의 과거 대화 기록을 읽는 일이므로 묵시적 동의로 진행하지 않는다. 무엇을 읽고 무엇을 남기는지 먼저 말한다.

| | 내용 |
|---|---|
| 읽는 것 | `~/.claude/projects/**/*.jsonl`의 사용자 발화 (`type:user` & `isSidechain:false`) |
| 뽑는 것 | 아래 5종의 **패턴과 빈도** |
| 남기는 것 | `mentee-profile.md`에 요약 몇 줄. **발화 원문을 옮겨 적지 않는다** |
| 안 하는 것 | 코드·비밀값·업무 내용 추출, 외부 전송 |

뽑는 것:

1. **커밋·PR·리뷰를 실제로 뭐라고 부르는가** → 두 스킬의 `description` 트리거 문구를 그 말버릇에 맞춰 보강한다. 이게 이 단계의 주목적이다
2. **판단 위임 발화의 빈도** — "알아서 해줘", "다 진행해줘", "너가 판단해서" → 잦으면 D등급 개입(밸런스 수치·세이브 스키마·정산)이 실제로 걸릴 지점이 많다는 뜻
3. **자기 코드를 되묻는 발화** — "내가 올린 PR인데 이거 어떻게 구현돼 있음?" → 이해 부채가 이미 쌓인 영역의 직접 증거
4. **레포·스택 분포** → `## 영역별 숙련도` 표의 초기 행을 만든다
5. **검증 보고 방식** — 증상을 장문으로 서술하고 있으면 O/X 체크리스트 전환의 효과가 큰 사람이다

**로그 범위를 먼저 확인한다.** `cleanupPeriodDays` 기본값이 30일이라 그 이전 기록은 지워져 있을 수 있다. **"로그가 한 달치다"는 "한 달 썼다"가 아니다.** 범위를 확인하지 않고 세면 초기 사용 패턴이 통째로 빠진 채 결론이 난다.

**자동화된 작업은 발화로 잡히지 않는다.** 세는 것은 "말한 횟수"지 "한 횟수"가 아니다. 전역·프로젝트 `CLAUDE.md`에 `"작업이 완료되면 별도 지시 없이 커밋한다"` 같은 규약이 있으면 그 작업은 **매번 일어나면서 발화는 0에 수렴한다.** 빈도를 세기 전에 그 규약부터 읽는다.

> 빈도가 낮게 나온 항목은 두 가지 중 하나다 — **정말 안 하거나, 말 없이 하거나.** 후자를 전자로 읽으면 트리거를 엉뚱한 데 붙인다. 이때 답은 발화 트리거를 늘리는 게 아니라 **훅으로 잡는 것**이다.

또한 이 축은 Claude Code 세션만 본다. 다른 도구(codex 등)나 채팅에서 하던 작업은 안 보인다. **한 도구의 로그만 보고 전체 작업을 판단하지 않는다.**

### 2-4. 불일치는 사용자가 판단한다

2-1의 자기 보고와 2-2·2-3의 관측이 어긋나면 **고쳐서 저장하지 않는다.** 어긋난 지점을 보여주고 어느 쪽으로 갈지 묻는다.

> "익숙한 영역으로 UE를 꼽으셨는데 세션에서는 액터 수명 관련 질문이 반복됩니다. 프로필의 강한 축을 조정할까요?"

자기 보고가 맞고 관측이 우연일 수 있다. 판정 권한은 사용자에게 있고, 이 단계는 재료만 제공한다.

### 2-5. 스캔이 못 보는 것 두 층

**빈도가 0에 가깝다고 안 하는 게 아니다.** 스캔은 "말한 횟수"만 센다. 실제로 안 보이는 것은 두 층이다.

| | 어디서 일어나나 | 스킬이 잡을 수 있나 |
|---|---|---|
| **말없이 한다** | LLM 안 (자동 커밋 규약 등) | **훅으로 잡는다** |
| **밖에서 한다** | IDE·GitHub 웹·터미널 | **못 잡는다** — 2-6 |

첫 층은 조치가 있다. 둘째 층은 조치가 없고 **범위 축소를 인정하는 것**이 조치다.

### 2-6. LLM 밖에서 하는 작업 — 범위를 좁히고 그 사실을 남긴다

IDE에서 커밋하고, GitHub 웹에서 리뷰 코멘트를 달고 머지 버튼을 누르는 사람이 있다. 이 경우 **두 스킬이 덮는 범위가 실제로 줄어든다.** 이걸 인정하지 않으면 3주 뒤 빈 원장을 보고 "안 쓰네"로 오진한다.

**절대 하지 말 것 두 가지.**

- **git 훅(`pre-commit`·`post-commit`)을 심어 IDE 커밋을 가로채는 것.** IDE 커밋 흐름에서 대화형 게이트는 붙지 않고, 붙어도 사용자가 답할 화면이 없다. 커밋을 느리게 만들면 그 다음에 일어나는 일은 학습이 아니라 **훅 삭제**다
- **"LLM 안에서 커밋하세요"라고 워크플로를 바꾸라고 요구하는 것.** 도구가 사람의 일하는 방식을 바꾸라고 요구하면 도구가 버려진다

**대신 하는 것.** 아래 셋 중 본인이 고른다.

| 선택 | 얻는 것 | 잃는 것 |
|---|---|---|
| **A. 명시 호출만** — `/mentor`, "PR 리뷰해줘"를 본인이 칠 때만 | 워크플로 그대로 | 자동 발동 없음. **`## 스킵 기록`이 무의미해지므로 1차 지표를 안 본다** |
| **B. 사후 배치** — 하루·한 주 끝에 "오늘 커밋들 이해 확인해줘" 한 번 | 부채 측정은 유지 | 커밋 시점의 맥락이 식는다. 예측 질문의 정확도가 떨어짐 |
| **C. 도입 보류** | — | 이 세트는 이 사람에게 맞지 않는다. **이것도 정당한 결론이다** |

고른 결과를 `mentee-profile.md`에 남긴다. **A를 골랐으면 `RATIONALE.md`의 `## 재는 것`에서 스킵률 항목을 지운다** — 발동하지 않는 경로의 스킵률은 항상 0이고, 0인 지표는 안심시키는 거짓 신호가 된다.

> **`pr-review-loop`는 사정이 조금 낫다.** GitHub 웹에서 리뷰하는 사람도 "이 PR 봐줘"라고 한 번은 부르는 경우가 많고, 이 스킬은 원래 사용자 호출로 시작한다. 반면 `senior-mentor` 모드 C/L은 훅 의존이라 밖에서 커밋하면 **발동 경로가 통째로 사라진다.** 둘을 같은 강도로 도입하려 하지 않는다.

---

프로필은 고정값이 아니다. 낯설던 영역이 익숙해지면 갱신한다. **`## 영역별 숙련도`가 `L → C` 승격을 기록하면 그때가 갱신 시점이다.**

### 2-7. 각 스킬의 `RATIONALE.md` 만들기

이 레포의 스킬은 모두 성공 기준을 `RATIONALE.md`에 두고 `SKILL.md`에서는 참조만 한다. **배포판에는 이 파일이 없으므로 받는 쪽이 직접 만든다** — 원작성자의 관측 기록은 받는 쪽에 의미가 없기 때문이다.

받은 스킬마다 `RATIONALE.md`를 만들고 아래 다섯 섹션을 채운다. **각 스킬의 `SKILL.md` 끝에 있는 "성공 기준 · 존재 의의" 절이 그 스킬의 시드다** — 거기 적힌 기준을 옮겨 담는다.

> **플러그인으로 설치했다면 스킬 폴더에 만들지 마라.** 플러그인은 설치 시 캐시 디렉터리로 복사되고, `/plugin update` 때 그 디렉터리가 갈린다 — 거기 쌓은 관측 기록은 업데이트 한 번에 사라진다. `<기준 폴더>/rationale/<스킬명>.md`에 두고 `SKILL.md`가 말하는 "같은 폴더"를 그 경로로 읽는다. 원장 두 개가 이미 기준 폴더에 있으므로 자리로도 맞다.

| 섹션 | 담는 것 |
|---|---|
| `## 없애려는 것` | 이 스킬을 왜 쓰기로 했는지. **본인이 실제로 겪은 반복 비용**을 적는다. 없으면 이 스킬은 본인에게 필요 없는 것이다 |
| `## 재는 것` | 아래 기준 |
| `## 원장 위치` | **그 스킬이 실제로 적재하는 파일 경로.** 스킬마다 다르다 — 이해 부채 원장을 쓰는 것, 자기 원장을 따로 쓰는 것, 그리고 **적재처가 아예 없는 것**(사람 관측치로만 재는 스킬)이 섞여 있다. 없으면 `없음`이라고 적는다. **비워두거나 남의 원장을 적지 않는다** — `skill-checkup`이 이 칸을 읽어 기록 층을 세는데, 그 스킬이 안 쓰는 파일을 가리키면 정상 작동을 절차 이탈로 오진한다 |
| `## 관측` | 점검할 때마다 한 줄. `날짜 \| 대상 \| 관측 \| 판정` |
| `## 미해결 후보` | 관측에서 나왔지만 아직 반영 안 한 개선안 |

**기준은 메커니즘에 딸린 것이라 사람이 바뀌어도 같다.** 그대로 옮겨 적는다.

**`pr-review-loop`**

- *절차* — 사용자가 "에디터에서 확인할 항목 알려줘"를 **직접 요구하지 않게 되면** 성공. 이해도 대조를 하는 PR에서는 질문 네 개에 답한 직후 응답이 그 시점이고, 그 외에는 첫 응답이다. **순번이 아니라 요구 여부로 잰다** — 이해도 대조는 리뷰 결과를 전부 막으므로 체크리스트도 같이 막힌다. 순번으로 재면 작동하는 세션이 실패로 잡히고, 그 잣대를 맞추려다 체크리스트를 먼저 흘려 이해도 대조를 죽인다
- *학습 루프* — `## 대조 집계` 분포가 **모름 → 짚었으나 틀림 → 일치** 쪽으로 이동하면 성공

**`senior-mentor`**

- *스킵률 (1차)* — 3주 연속 스킵이면 **시스템 자체를 재설계한다.** 이 스킬의 1차 실패 모드는 "예측이 틀리는 것"이 아니라 **"조용히 안 쓰게 되는 것"**이다
- *대조 집계 분포 (2차)* — 위와 같은 표를 본다

> **2-6에서 A(명시 호출만)를 골랐으면 스킵률 항목을 지운다.** 자동 발동이 없으면 스킵할 것도 없어 항상 0이 나오고, **0인 지표는 아무 문제가 없다는 거짓 신호**가 된다. 그 경우 1차 지표는 "명시 호출 빈도"로 대체하거나 아예 두지 않는다.

**두 스킬의 분포는 합쳐서 본다.** 원장이 하나이므로 자동으로 그렇게 되며, 나누면 "팀원 코드는 이해하는데 내 코드는 모르는" 상태가 지표에서 사라진다.

3개월간 분포가 안 움직이면 메커니즘 문제가 아니라 **같은 영역에 반복 노출이 안 되고 있다는 신호**다. 절차를 고치지 말고 작업 배분을 본다.

### 2-8. 지식 볼트 — 범용 지식을 어디에 쌓을지 정한다

원장(`comprehension-debt.md`)은 **재는 파일**이지 읽는 파일이 아니다. 항목이 `[레포/스택]`으로 태깅되므로 **프로젝트가 끝나면 같이 죽는다.** 그런데 부채 중 일부는 프로젝트를 넘어 남는다.

| 부채 항목 예 | 성격 |
|---|---|
| "이 프로젝트의 챕터 전환은 레벨 전환이 아니라 스폰테이블 교체" | **프로젝트 한정** — 원장에서 끝 |
| "무엇이 영속 스키마에 들어가고 무엇이 런타임 전용인가" | **범용** — 엔진·언어가 바뀌어도 같은 문제 |
| "객체 수명·소유권 경계" | **범용** |

범용 쪽은 원장 밖에 쌓아야 프로젝트가 끝나도 남고, `.claude` 폴더에 들어가지 않고도 다시 읽을 수 있다.

**어디에 쌓을지를 묻는다.** 사람마다 다르고, 없는 곳에 쓰면 조용히 실패한다.

| 선택 | 확인할 것 |
|---|---|
| **로컬 마크다운 볼트** (Obsidian 등) | 볼트 절대경로 · 기술 노트가 이미 쌓이는 하위 폴더 · git 추적 여부 |
| **노션** | 노션 MCP가 **인증돼 있는지**. 세션마다 인증이 끊기면 적재가 조용히 실패한다 |
| **쌓지 않는다** | 원장만 쓴다. 프로젝트 종료와 함께 부채 기록도 종료된다는 뜻 |

**MCP 기반을 고르면 도입 시점에 쓰기 테스트를 한 번 한다.** 읽기만 되고 쓰기가 막힌 경우가 있고, 그건 적재를 시도할 때까지 안 드러난다.

고른 결과와 경로를 `mentee-profile.md`에 남긴다. 노트 형식·복습 트리거는 이 문서의 범위 밖이다 — 볼트 쪽 설계로 따로 다룬다.

## 3. 훅 (선택 — 없으면 수동 발동)

`senior-mentor`의 모드 C/L은 `PostToolUse` 훅이 커밋·PR을 감지해 발동시킨다. 훅이 없으면 **사용자가 매번 "멘토 리뷰"라고 말해야 하고, 그러면 이 스킬은 조용히 안 쓰이게 된다** — 그게 이 스킬의 1차 실패 모드다.

**2-6에서 A(명시 호출만)나 C(보류)를 골랐으면 이 단계를 건너뛴다.** 밖에서 커밋하는 사람에게 훅은 걸리지 않는다.

그 외의 경우 **세팅 여부를 여기서 명시적으로 묻는다** — 훅은 모든 커밋에 걸리는 상시 장치라 말없이 심지 않는다. 파일은 배포판에 포함되어 있다: `senior-mentor/hooks/comprehension-gate.ps1`. 이 훅은 Claude Code의 `PostToolUse` 형식 전용이다 — codex 등 다른 에이전트에서는 훅 없이 명시 호출로 쓴다.

**PowerShell 스크립트라 기본은 Windows 대상이다.** macOS/Linux에서는 PowerShell 7(`pwsh`)을 설치하고 아래 등록 예시의 `powershell ...`을 `pwsh -NoProfile -File "<경로>"`로 바꾸거나, 훅 없이 명시 호출로 쓴다.

`comprehension-gate.ps1`이 하는 일:

- 커밋·PR 도구 호출을 감지
- `확장자 화이트리스트 AND NOT 경로 블랙리스트`로 코드 파일만 통과
- 통과하면 이해 확인을 요청하는 컨텍스트를 주입

세팅하기로 했으면:

1. 스킬 폴더의 `senior-mentor/hooks/comprehension-gate.ps1`을 `<기준 폴더>/hooks/`로 복사한다
   - 플러그인으로 설치했으면 원본이 캐시 디렉터리에 있다. `/plugin` 화면에서 설치 경로를 확인하고 그 아래 `senior-mentor/hooks/`에서 가져온다. 복사한 뒤 절대경로로 등록하므로 이후 업데이트와 무관하게 동작한다
2. 스크립트의 `$denyPat` 주석 처리된 첫 줄에 **본인의 문서 레포·노트 볼트 경로를 채운다** — 코드 확장자가 있어도 이해 확인 대상이 아닌 곳이다
3. `settings.json`에 등록한다 (전체 구조 기준 — 이미 `hooks` 키가 있으면 `PostToolUse` 배열에 항목만 추가):

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "powershell -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File \"<기준 폴더 절대경로>\\hooks\\comprehension-gate.ps1\""
          }
        ]
      }
    ]
  }
}
```

matcher `"Bash"`는 Bash 도구로 실행된 커밋을 잡는다. 커밋이 PowerShell 도구로 실행되는 구성이면 `"Bash|PowerShell"`로 넓힌다.

> **PostToolUse는 아무것도 차단하지 못한다.** 커밋은 이미 끝난 뒤라 되돌리라고 제안하지 않는다. 고칠 게 있으면 후속 커밋이다.
>
> **한글이 든 `.ps1`은 UTF-8 BOM으로 저장한다.** BOM 없이 저장하면 Windows PowerShell 5.1이 cp949로 읽어 구문 오류로 죽는다.

훅 없이 쓰려면 스킬을 명시 호출(`/mentor`)하고, `## 스킵 기록`을 더 엄격하게 본다.

## 4. 전역 `CLAUDE.md`가 전제하는 것

스킬이 "사용자는 이렇게 답할 것"을 가정하는 부분이다. 규칙이 없으면 형식이 매번 달라지고 스킬이 해석에 실패한다.

### 게임플레이 검증 보고 형식 (`pr-review-loop` 4단계가 의존)

에디터에서 사람이 직접 확인해야 하는 항목은 **자유 서술로 받지 않는다.**

- 항목은 **PR 리뷰 시 생성**한다. 검증할 때 새로 만들지 않는다
- 결과는 **`O` / `X` / `?` + 한 줄**로 받는다
- **`?`는 두 가지를 가리키므로 어느 쪽인지 확인한다** — "확인할 수단이 없다"(하네스 부재 → 백로그)와 "수단은 있는데 못 봤다"(미검증). 섞으면 백로그에 없는 문제가 쌓인다

### 보고서 작성 원칙 (두 스킬 공통)

사람이 읽을 산출물에 AI가 읽기 좋은 표현을 그대로 쓰지 않는다. 내부 상태값·변수명·절차 번호가 본문에 노출되면 그건 사람이 읽으라고 만든 게 아니다.

> 판단 기준: **이 문장이 읽는 사람의 행동을 바꾸는가.** 바꾸지 않으면 뺀다.

### 커밋 규약 (`senior-mentor` 모드 R이 의존)

- 사용자 작성분과 AI 작성분을 **분리 커밋**한다
- push는 사용자가 명시 요청할 때만
