# B안 백지 분석 프롬프트 — 원문

서브에이전트에 그대로 넣는다. **아래 블록은 문구를 다듬지 않는다.** 치환할 곳은 중괄호 넷뿐이다.

- `{기간}` — 잔존 로그의 첫날 ~ 마지막날 (예: `2026-07-06 ~ 08-05`)
- `{세션수}` — 스크립트가 찍은 세션 개수
- `{추출파일 절대경로}`
- `{줄수}` / `{용량}`

```text
아래 파일은 한 개인 사용자가 {기간} 동안 Claude Code로 작업한 {세션수}개 세션에서 추출한 **사용자 프롬프트 원본**이다. 도구 결과와 알림 노이즈는 제거되어 있고, 세션별로 `### [프로젝트디렉터리] 날짜 세션ID` 헤더 아래 그 사람이 실제로 입력한 말이 순서대로 담겨 있다.

파일: {추출파일 절대경로} (약 {줄수}줄, {용량} — 반드시 offset/limit을 나눠 **전체를 끝까지** 읽어라. 앞부분만 읽고 판단하지 마라.)

## 네가 할 일

이 사람이 무엇을 하고 있는지 스스로 파악한 뒤, **이 사람의 작업 방식을 개선할 방법을 자유롭게 제안**하라.

## 중요한 제약

- 나는 이미 나름의 결론을 갖고 있지만 **의도적으로 알려주지 않는다.** 내 틀에 맞추려 하지 말고 백지에서 읽어라.
- 어떤 정해진 카테고리나 산출물 형식에 맞출 필요 없다. 네가 보기에 중요한 것을 중요한 순서대로 말하면 된다.
- 특히 **다른 사람이라면 놓칠 법한 관찰**을 원한다. 눈에 띄는 반복 작업을 나열하는 건 누구나 한다. 그것 말고:
  - 이 사람이 **자기도 모르게 반복적으로 지불하고 있는 비용**은 무엇인가
  - 이 사람의 요청 방식 자체에 있는 **비효율이나 나쁜 습관**은 무엇인가
  - 프롬프트에 드러나는 **인지적 공백**(모르는 걸 모른다고 인식조차 못 하는 지점)은 어디인가
  - 여러 프로젝트에 흩어져 있지만 실은 **같은 문제인 것들**은 무엇인가
  - 이 사람이 지금 하고 있는 일 중 **하지 말아야 할 일**, 또는 방향이 잘못된 것은 무엇인가
- 근거는 반드시 파일의 실제 내용에서 인용하라. 추측으로 지어내지 마라. 확신이 없으면 "이건 추정"이라고 명시하라.
- 듣기 좋은 말은 필요 없다. 냉정하게 써라.

## 출력

한국어로, 구조화된 보고서 형태로. 분량 제한 없음. 각 제안에는 근거가 된 세션(날짜/프로젝트)을 붙여라.
```

## 손대면 안 되는 부분

날카로움은 "자유롭게 분석해줘"에서 나오지 않는다. 아래 넷이 실제 발생기다.

| 요소 | 없으면 생기는 일 |
|---|---|
| 질문 축 5개 | 반복 작업 목록만 나온다. 그건 누가 봐도 보이는 것이라 새 정보가 0이다 |
| "전체를 끝까지 읽어라" + 분량 명시 | 앞 몇 세션만 읽고 일반론을 쓴다. 반복 패턴은 전체를 봐야 잡힌다 |
| 근거 인용 강제 + "확신 없으면 추정이라고 명시" | 그럴듯한 창작이 섞여 들어오고, 나중에 어느 게 창작인지 구분이 안 된다 |
| "듣기 좋은 말 필요 없다" | 지적이 완충재에 싸여 나와 우선순위를 못 매긴다 |

앵커를 없앤다는 건 분류 틀과 요청자의 결론을 안 준다는 뜻이지, 방향을 안 준다는 뜻이 아니다. 질문 축까지 빼면 백지 분석이 아니라 요약이 나온다.

## 상황에 맞게 고칠 부분

- **"나는 이미 나름의 결론을 갖고 있다"** — 요청자가 먼저 분석해 본 게 있을 때만 성립한다. A안을 병행하지 않는 실행이면 이 줄을 빼고 *"정해진 카테고리에 맞출 필요 없다. 네가 중요하다고 보는 순서대로 말해라"* 만 남긴다.
- **모델** — 백지에서 구조를 잡는 작업이므로 fable을 기본으로 한다.
- **실행 위치** — 추출 결과가 수백 KB이므로 파일을 나눠 읽을 수 있는 도구 쪽에서 돌린다. 채팅에 첨부한다면 기간을 좁혀 다시 추출한다.
