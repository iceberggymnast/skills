# 산출물 골격

파일명 `세션전수분석_YYYY-MM-DD.md`. 배치 경로는 `SKILL.md` 6단계 참조.
프론트매터는 `date`, `tags: [claude-code, 워크플로우, 자동화, 회고]`.

절 번호는 고정한다. 나중에 축을 덧붙이거나 정정할 때 §5.3 · §8.4 3-1 같은 참조로 가리키게 되므로, 번호가 흔들리면 정정 이력이 끊긴다.

---

## §1 스크레이핑 방법과 규모

표 한 개: 세션 파일 수·용량 / 프롬프트 복원 성공 세션 / **잔존 기록의 범위** / 필터 조건.

### §1.1 이 분석의 데이터 한계

월별 분포를 그대로 싣고, 언제부터 썼는지와 대조한다. 잘려나간 구간이 있으면 그 사실을 여기서 못박는다. 이후 모든 수치는 잔존분에 대한 통계라는 단서가 여기 한 번만 붙으면 된다.

## §2 작업 전체 지도

축별 표: 작업 축 / 세션 수 / 용량 / 실제 하는 일. 프로젝트 디렉터리 이름이 아니라 **하는 일**로 묶는다.

## §3 환경 결함 (있을 때만)

반복 재시도로 새는 비용이 로그에 잡히면 여기서 규모 → 근본 원인 → 재현 → 조치 순으로 쓴다. 없으면 절을 비우지 말고 통째로 뺀다.

## §4 A안 — 분류 틀을 가진 분석

스킬 / 플러그인 / 에이전트 / CLAUDE.md 네 칸으로 나눈 제안 표. 각 항목에 **반복 횟수 근거**를 붙인다.

## §5 B안 — 백지 분석

서브에이전트 결과를 소절로 나눠 싣는다. 요약하지 말고 지적의 날을 유지한다. 각 소절에 근거 세션(날짜/프로젝트)이 붙어 있어야 한다.

## §6 B안 주장 중 사실과 다른 것

**이 절이 비어 있으면 §7 검증을 안 한 것이다.** 표 두 칸: 주장 / 확인 결과. 판정 근거(파일 크기, 최종 수정 시각, 커밋 해시)를 같이 적는다.

## §7 두 분석의 교차 지점

합치 항목 표: A안 표현 / B안 표현. 갈라지는 지점도 같이 적는다 — 그쪽이 대체로 더 중요하다.

### §8.2 뺀 것과 그 이유
### §8.2-1 그대로 유지한 것 (격하·조건 변경 포함)
### §8.3 더한 것 (B안 발)
### §8.4 최종 산출물 — 단계 0/1/2/3

단계 표에는 **작동 확인 방법** 열이 반드시 있다. 이게 없으면 만든 뒤 소비되는지 알 방법이 없다.

- 단계 0 — 파일 편집만으로 끝나는 것
- 단계 1 — 반복 비용이 가장 큰 것
- 단계 2 — 누수 차단 구조
- 단계 3 — 실행 전 결정이 필요한 것 (여기에는 "결정할 것" 열)

## 나중에 덧붙이는 절

축을 늘려 재검토했을 때 §1~9를 고쳐 쓰지 않고 §10 이상으로 덧붙인다. 앞 절의 결론이 뒤집히면 원문을 지우지 말고 해당 번호를 인용해 정정 표를 만든다(`§8.4 실행 항목 변경`).

- codex 로그
- 채팅 기록
- 각 레포 커밋 로그

각 축에도 §1.1과 같은 **그 축의 데이터 한계** 소절을 붙인다.
