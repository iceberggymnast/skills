# 판정 요청 — git-writing

이 초안은 팀원이 읽을 PR·이슈 본문이다. 당신은 이 초안을 쓰지 않았고, 다시 쓰지도 않는다. 걸리는 문장을 인용하고 **그 문장만 바꾼 교체안**을 낸다. 본문 전체를 고쳐 쓴 결과물은 받지 않는다 — 통째로 다시 쓰면 작성자와 같은 리듬이 돌아온다.

- 초안: `{본문 파일 경로}`
- 린트 출력: `{린트 출력 파일 경로}`
- 규칙 원문: `{SKILL.md 경로}`의 공통 규칙 1~6

## 판정 항목

항목마다 걸린 문장이 없으면 "없음"이라고 쓴다. 비워 두거나 총평으로 대신하지 않는다.

- **A. 린트가 짚은 문장** — 각각에 교체안을 내거나, "그대로 둠"과 이유 한 줄. 검증 체크리스트처럼 짧은 단정이 맞는 자리, "조용히 넘어갔다"처럼 사실을 정확히 말하는 문장은 그대로 둔다.
- **B. 주어가 현상인 문장** ("상태가 갈라집니다", "값이 무너집니다") — 무엇이 무엇을 하는지로 바꾼 교체안 (규칙 1-b).
- **C. 비유·극적 동사가 사실의 자리에 선 문장** — 실측·조건·호출 순서로 바꾼 교체안. 사실을 모르면 지어내지 말고 "확인 필요: 무엇을 확인해야 하는지"로만 표시한다 (규칙 2).
- **D. 참조 코드·전문용어가 설명 없이 처음 등장하는 곳** — 설명은 초안이나 링크된 문서에서 확인되는 것만 붙인다. 모르면 "설명 필요"로만 표시한다 (규칙 3).
- **E. 실행하지 않은 검증이 실행한 것처럼 적힌 곳** — "미실행"으로 표시하는 교체안.
- **F. 어미 혼재, 반말 지칭** (규칙 5).

## 출력 형식

```
L{줄 번호}: "원문 문장" → "교체안"  (항목 A~F 중 하나, 근거 한 줄)
```

이 형식 밖의 총평·칭찬·요약은 쓰지 않는다. 교체안은 원문과 같은 정보를 담는다 — 밀도를 낮추려고 내용을 빼지 않는다.
